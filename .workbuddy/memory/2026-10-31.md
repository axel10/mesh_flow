# 2026-10-31

## mesh_flow 性能审计 + 优化落地

审计（flutter test / debug VM，9409 顶点）：
- `WarpGrid.buildVerticesWithParams` 同口径同步测量 0.20 ms/帧（早期 0.477 是 async 计时口径放大的假数，已作废）。
- 每顶点 12 次 sin + 4 次 exp；JIT 已会 CSE/LICM 掉一部分（`sin(p[i])`、`sin(πv)`），真正剩下的热点是 4 次 tanh。

已改动（视觉逐像素一致，29 个预设 × 2 个时间点验证）：
1. `MeshFlow` 改 `CustomPainter.repaint` 驱动（`ValueNotifier<int> _repaintTick`），动画不再 setState；
   顶点改在 `_buildFrame(Size)` 里现算。新增 `MeshFlowFrame` + `MeshFlowPainter.frameBuilder`。
2. 背景包 `RepaintBoundary`。**关键坑：只加 RepaintBoundary 无效，setState 每帧重建会把整棵子树拖进重绘，
   必须同时改成 repaint 驱动**，否则子节点仍 30/30 帧重绘。
3. `WarpGrid`：正弦查表 + `sin(p[i])`/行折叠/列折叠提到循环外 + texCoords 整帧复用。0.21 → 0.15 ms。
4. `CoverProcessor`：`ui.instantiateImageCodec` 替代手动 buffer/descriptor，补 `dispose()`（image/codec/picture）。
5. 整帧（含重建+全页重绘）0.455 → 0.164 ms；子节点重绘 30/30 → 0/30。

- 基准 `test/_bench_mesh_frame_test.dart` 保留：逐像素对齐「改造前算法」+ A/B 计时。
- `test/mesh_flow_test.dart` 新增「网格动画确实逐帧上屏」用例（防有人改回 setState 或漏接 repaint）。
- 已知环境限制：palette → 纹理这条异步链路在 flutter_test 里拍不到（`picture.toImage` 需真异步），
  改动前后都一样，不是回归。
- CHANGELOG 已记 Unreleased。
